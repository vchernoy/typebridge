# Current UI

This describes the implemented workspace. [#123](https://github.com/vchernoy/typebridge/issues/123) records the approved layout; [#137](https://github.com/vchernoy/typebridge/issues/137) tracks follow-up improvements. Future product ideas remain in the [PRD](PRD.md) and [roadmap](ROADMAP.md).

## Normal workspace

The top bar contains a small TypeBridge heading, the document title edited in place, a ▾ **Documents** menu, compact save state, **Latin / Кириллица** typing switch, Focus and Settings. The switch is a real checkbox with the switch role and accessible name “Кириллица”; its description gives the configured shortcut. Clicking a word chooses that typing mode; Space toggles it. Shortcut labels (hint, tooltips, Settings picker, shortcut sheet) follow the platform: Apple symbols in Apple order with no separators on Mac, iPhone and iPad (⌃⇧Space, ⇧⌘Z, ⌘F), words joined by + elsewhere (Ctrl+Shift+Space). The visible hint appears only where a keyboard is likely: it is hidden at 640 px and below and on touch-only devices (no fine pointer), where the switch is tapped; it stays the switch's accessible description everywhere.

The document menu lists saved documents and offers New document, Import…, Export as TXT, Export as JSON, **Share link…** and Delete…. Share link… makes a link that opens the document as a read-only page ([sharing](SHARING.md)). **Open in another window** ([#159](https://github.com/vchernoy/typebridge/issues/159) W2, [ADR](adr/159-comparison-window.md)) opens the latest committed saved copy in a second window or tab (`/editor.html?doc=…&mode=view`) as a read-only companion showing **Saved version · Read-only**; browsers may open a tab rather than a window, and a blocked pop-up leaves your text untouched with guidance to allow pop-ups. Unsaved typing is never sent; with no saved copy a dialog explains and offers Cancel only, and never turns on Autosave. The companion cannot edit, convert, replace, undo, create, import or delete, never saves, and can switch to other saved documents; Find, Go to line, selection, copy and export still work. It refreshes to the latest saved version when another window saves, renames or deletes the document (**Updated to the latest saved version**, or the missing state after a delete); the badge tooltip names the represented revision, and focusing the window rereads storage if a message was missed. An editing window with unsaved or private text is never replaced: it shows **A newer saved version of this document exists in another window. Your text here has not been changed.** (#159 W3). Only one browser tab edits a document at a time (#159 W4). A second ordinary window or tab on the same document looks like a normal editor: it shows the saved text with the usual **Saved** state and no read-only badge or notice. Clicking or typing in its text or title, or using Undo, Redo, Delete, Convert, Clear or Replace there, moves editing to that window first, so any window can edit and rename. Only one window holds editing at a time; the others follow its saved text. **Focus handoff (#175 step 4):** clicking or typing in the text of the window that is not editing asks the editing window to flush and yield; the new owner rereads saved text (or receives unsaved text in memory within the same tab only), and keys typed during the handoff are kept. Across real tabs, private/unsaved text is never sent — the reader shows **Edit here** with a warning instead. A suspended owner may be taken over after a short wait. When the editing window closes or switches away, the read-only window can also become the editor when focused (**You can edit this document in this window now.**). When the document a window shows is deleted in another window or tab, that window keeps its text and shows **This document was deleted in another window. Its text is still here.** with **Keep as new document** (saves the text and title here as a new document this window edits) and **Close** (opens the most recent other document, or a new one); typing or pasting into its text or title keeps it as a new document and applies the keys. It never tries to take over the deleted document. Delete warns when the document is also open in another host window. If a window loses ownership while unsaved, it keeps text/title/history in memory and asks before discarding on switch. Without Web Locks every document is read-only. The in-page **Split editor** from [#159](https://github.com/vchernoy/typebridge/issues/159) was **removed** in [#175](https://github.com/vchernoy/typebridge/issues/175) step 10. Multiple document views use movable **editor windows** (iframe instances) with tab-style editing and free/stacked layout — see [ADR 175](adr/175-editor-windows.md). The app opens at `/` as the multi-window host (`/host.html` redirects there; the single editor is `/editor.html`). It supports multiple editor windows (New window, drag title bar, resize, tile, close with unsaved prompt). Each host window shell is a named region (`role="region"`) labeled with the document title; the active shell uses `aria-current`. **F6** cycles focus to the next window’s editor in the order the windows were opened (**Shift+F6** goes back; both also work from the update notice) (raises z-order in free layout; works when windows are stacked; under host Focus it maximizes the next window while keeping the prior free/stacked geometry for exit; works from the host title field as well as the editor). F6 is ignored while a confirmation dialog is open so the modal trap stays intact. Cycling into a window that shows the same document hands editing to it (focus decides editing). The host claims F6 for window cycling, so it does not reach the browser’s own region cycle. The embedded keyboard-shortcuts sheet lists F6 / Shift+F6 as Next / previous editor window. **Layout** in Settings chooses Auto, Free windows, or Stacked: Auto uses free windows on a fine-pointer/hover desktop and stacked full-width windows on a phone-sized or coarse-pointer viewport; Stacked keeps a height grip per window. Focus mode on the host maximizes the active window and restores the prior free/stacked layout on exit. Host Focus takes two lines: the window title bar carries the TypeBridge name, the document title with ✎, the shared **Latin / Кириллица** switch and an icon-only ⚙ Settings (the host toolbar, move grip and × are hidden; on narrow screens the name and shortcut hint drop out), and the window shows one row with ▾, the save state and **Exit ⛶ (Esc)** (Exit ⛶ on narrow screens). Settings stays available in host Focus. Windows have no text-box resize corner; the window edges size the text. Verification packaging and honest device/AT limits for the windows work live under [evidence/175](evidence/175/README.md). The single editor page `/editor.html` still offers **Open in another window** for the W2 `mode=view` comparison popup; embedded host windows hide that control because the host already manages windows. Cross-window Edit here (#164) stays paused; same-tab focus handoff replaces that protocol for the new windows goal. Opening the Documents menu focuses the search box (#175 step 8). The list shows each document’s title, a short text preview, last-edited time, and a mark when that document is open in another host window. Typing in search filters by title or body. Escape, a click outside or an action closes the menu; actions return focus to the trigger. Pointer selection closes the list, while keyboard arrow navigation keeps it open. New documents get distinct defaults (`Untitled document`, then `Untitled document 2`, …). The host page has one compact top bar: the TypeBridge name, New window, Tile side by side, Tile stacked, the shared **Latin / Кириллица** switch with its shortcut (one switch for every window; the shortcut in any window flips it) and Settings. The bar stays on one line: when it would wrap it first drops the shortcut hint, then shows New window, both Tile buttons and Settings as icon buttons (their names stay for assistive tech). Free windows show a small grip in the bottom-right corner; every edge and corner resizes. Stacked windows hide the ☰ move grip (they do not move); it stays a keyboard stop for Ctrl/⌘+Shift+Up/Down height resize and shows while focused. Each window is flat (no inner card): its title bar, then one row with ▾, the save state, the editing tools and a Focus icon (the tools move to a second line in narrow windows), then the text, which fills the window. Windows do not repeat the mode switch, the About link (it lives in Settings → About your documents), the visible “Your text” label (still the editor’s accessible name) or the transliteration status, and a mode change is announced only in the window where it was made. On the host page the window title bar shows the document title as a text field for rename in place, with a ✎ **Rename document** button beside it; embedded editors hide the in-frame title field. **Documents → Rename…** focuses the title (the window's title bar on the host page) with the name selected. Documents are browser-local; code, storage identifiers and the export format retain their `draft` names ([#108](https://github.com/vchernoy/typebridge/issues/108)).

The editing toolbar holds Undo/Redo, To Cyrillic and To Latin (convert selected text), Find and Copy. Its **⋯** menu contains Go to line, Clear text and Keyboard shortcuts. The shortcut sheet is a two-column list of actions and keys (with Escape and reserved-shortcut notes), using platform labels, the current typing shortcut and all fixed bindings, with a link to the existing shortcut setting; capture/remapping remains #69. Find/Replace values and their separate Undo/Redo histories follow the shown document; viewers keep local searches in memory only. Privacy switches leave these values visible and change only whether they are saved (#257 step 2b). Find/Replace and Go to line open on demand through buttons or Cmd/Ctrl+F and Cmd/Ctrl+G; Escape or × closes them and returns to the editor. Each Find/Replace label stays with its field. Match case and Regex are labeled checkbox chips in the find bar. Previous/Next match use ↑/↓ buttons with accessible names. The status shows the total before navigation and the current position (for example “2 of 5”) after navigation; matching rules are unchanged. See [editor behavior](EDITOR-BEHAVIOR.md) for conversion, search and history details.

A compact dot and label beside the title shows Saved, Saving…, Not saved or Save failed ([#131](https://github.com/vchernoy/typebridge/issues/131), [#156](https://github.com/vchernoy/typebridge/issues/156)). It is the only visible save-state label; a private document (Autosave unchecked) shows Not saved. Routine “Saved locally” / “Saving…” announcements stay in the lower live region for assistive tech but are not shown again visually. Action feedback, conflict notices and storage/privacy warnings remain visible under the editor beside character/word/read-time counts (with singular forms) and caret position. Long titles ellipsize in the field; the full title remains in the field value and tooltip. Copying or exporting does not dismiss an unsaved warning.

## Settings and privacy

Settings opens a **non-modal side panel**, so changes can be tried in the editor while it remains open. It contains the transliteration shortcut, mapping chart and custom rules editor, **Private session** (under Saving), Tab indents, Appearance, Layout (host only) and an About your documents section with storage/history/offline information. On the multi-window **host** page (`/`) there is one Settings panel for the page; changes apply to every window immediately. Embedded editors open that host panel (including from the keyboard-shortcuts sheet). The single editor page (`/editor.html`, opened directly or as the comparison popup) keeps its own panel. A short About your documents link under the editor opens that section in one step and returns focus when closed. Closing with Escape or × returns focus. Focus mode on `/editor.html` hides this panel; host Focus keeps it.

**Autosave** is a **per-document** checkbox in the editor chrome (on by default). Unchecking it marks that document private: nothing further about its text or title is written (no IndexedDB save, change records, reload backup or emergency journal). A **Private** marker appears while the document is private. Going private switches immediately, then tries one last save of the pre-private snapshot with `private: true` so the row reopens as private; a failed last save falls back to a flag-only update and may show a longer warning. It then offers **Keep saved copy / Delete saved copy** ([#257](https://github.com/vchernoy/typebridge/issues/257)): deleting removes the saved row, change records and backups while the text stays in the window privately. Checking Autosave again clears the document flag and resumes saving when writes are allowed.

Settings → **Private session: don't save anything** is the shared browser preference (same `typebridge.autosave.v1` key as the former Settings Autosave control, inverted). When on, every document in every window is private; each window’s Autosave checkbox stays off and disabled. Prefs sync (same-tab CustomEvent and cross-tab `storage`) shares only this global session — not per-document flags. Turning the session off restores each document’s own Autosave/private flag. Unsaved private changes can be lost on reload, tab discard or closing. Browser storage is specific to this browser/device and can be cleared or evicted; export important work. See [settings lifetimes](SETTINGS-PERSISTENCE.md) for storage and recovery limits. There is no account, sync, telemetry or text upload.

## Focus mode

Focus keeps the **same title bar controls** above the editor: title, ▾ document menu, save state, typing switch and Exit focus ([#104](https://github.com/vchernoy/typebridge/issues/104), [#136](https://github.com/vchernoy/typebridge/pull/136)). There is no separate document picker. Rename, switch and create use the same controls and save/conflict/discard handling as Normal mode without leaving Focus. The brand, Focus button, Settings, shortcut hint and editing toolbar are hidden. The editor and its history are preserved; Normal and Focus sizes are stored separately.

Escape from the editor or Cmd/Ctrl+Shift+Enter toggles Focus. The Exit button leaves it. Focus preference is restored after the selected document loads; see [settings lifetimes](SETTINGS-PERSISTENCE.md).

## Phones and resizing

At 640 px and below, the brand is visually hidden, the title/menu/save state occupy the first row, and the typing switch and icon-only Focus/Settings controls follow. In Focus mode, the switch and Exit follow the title row. The shortcut hint and toolbar separators are hidden and margins shrink. Convert buttons use shorter Cyr/Lat labels while keeping accessible names. At 400 px and below, Find and Copy use icons with their accessible names retained and 44 px targets. Aim for one editing-toolbar row at 390 px with system fonts; wider fonts or 320 px may wrap. Controls must never cause horizontal overflow. Coverage includes 320/390 px and a 24 px root font.

The editor has one custom corner grip ([#70](https://github.com/vchernoy/typebridge/issues/70)); iPhone Safari does not provide a usable native CSS resize grip. Dragging changes width and height. Keyboard users can focus the grip and use arrow keys to resize. Text selection and native editing remain available.

## Keyboard and accessibility

Escape closes one visible layer: confirmation dialog → Settings → document/More menu → Find/Go to line → Focus shortcut ([#132](https://github.com/vchernoy/typebridge/issues/132)). This also applies after focus moves into the editor. On the host page, Escape from an embedded editor closes the host Settings panel before Find/Go to line in that window. CSS-hidden panels do not intercept Escape. Composition, repeated/already-handled events and collapsed native select popups retain their ownership. Clear text, Delete document, Import, unsaved-change discard and emergency-backup discard use the same in-page confirmation dialog. Each names its action and safe alternative; the background is inert while the modal is open, Tab stays inside it, Escape takes the safe choice and focus returns after closing. Browser beforeunload warnings remain browser-managed.

Controls use semantic buttons, labels, dialogs, listbox/menu patterns and visible focus. The detailed status uses polite announcements; the compact save label does not duplicate them. Settings → Appearance offers System, Light or Dark; System follows device changes, manual choices persist in this browser and apply before the application bundle loads. The UI uses semantic color variables in `src/styles/base.css` (dark and light overrides in `src/styles/phone-themes.css`; `src/style.css` imports every stylesheet in cascade order) and has explicit forced-colors system styling. U5 preserved the existing colors. U7 makes the shared confirmation/shortcut dialog use the dark surface for readable text; further manual contrast checks are tracked in [#11](https://github.com/vchernoy/typebridge/issues/11). Aim for 44 px touch targets and preserve native selection, context menus and expected shortcuts. Automated browser checks are not real iPhone, OS input-method, screen-reader or 200% zoom verification; record those separately in [#11](https://github.com/vchernoy/typebridge/issues/11). [#105](https://github.com/vchernoy/typebridge/issues/105)'s Escape typing-mode toggle remains undecided.

## Updates

When a newer offline worker is waiting, a non-blocking New version available notice offers Reload or Not now. It never reloads automatically. Reload first saves or verifies a tab-local reload backup; if neither is available, editing stays open. Private edits are never silently written: an explicit discard/reload choice warns about losing private changes. Not now hides the notice for this tab's session. Activation failure leaves text on screen. Real browser termination and storage eviction remain outside these guarantees.

## Reset settings

Settings → Reset settings to defaults asks explicitly before resetting appearance (System), window layout (Auto), typing mode/shortcut, custom rules, Tab indents, Find options, Normal/Focus editor sizes and Focus preference. It does not reload the page, delete documents, change current text/history or clear Private session / per-document private flags. Partial storage failures are reported; they do not prevent other preferences from being reset.


A new private document that has never saved appears only in its window’s Documents list, marked **Private · Not saved**. It disappears on reload/close; its ID is omitted from restored host layout. Checking Autosave with Private session off saves it and starts normal metadata recording. Explicit Import remains an explicit save. Previously saved private documents continue reopening their last stored version.


**Documents → Clear this document’s saved data…** removes the shown saved document’s local data after a confirmation naming the saved copy, change records, backups and view metadata. Its text stays privately in the clearing window as an unsaved scratch document. Other copies show the existing deleted-elsewhere state. The action is disabled when there is no saved copy or this window cannot clear it.

**Settings → Clear local data…** removes all saved documents, records, backups, saved window layout and search/view metadata in this browser. It is separate from **Reset settings**: settings, Private session and offline access are kept. Confirmation says the operation cannot be undone and **every open TypeBridge window and tab will start with an empty document**. On success every page reloads (the host reloads all its iframes). The initiating window says **All local data was cleared**; others say **Storage was cleared in another tab**. The notice is consumed once on boot. Text, title, Find/Replace and their histories are discarded. Partial failure leaves pages open for retry. Blocked deletion stays pending, and partial erasure reports **Some local data could not be cleared** across open windows.
