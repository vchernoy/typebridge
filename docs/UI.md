# UI design specification

> Historical design intent, not a current feature inventory. See the [note at the top of the PRD](PRD.md) and the [README](../README.md) for implemented behavior.


## Visual direction
Quiet, spacious writing workspace; strong hierarchy, high contrast, understated blue accent. Use system fonts, generous line-height, clear labels and visible focus rings. No imitation of competitors' branding. Theme tokens for surface, text, muted text, border, accent, focus and error; test contrast in light and dark themes and forced-colors mode.

## Desktop layout
Compact header with TypeBridge name, theme selector and Settings. Above the main writing area: language/preset, Latin/Russian live-input toggle, optional dual-panel switch and accessible conversion actions. Editor dominates available width and height with a visible resize grip, keyboard-accessible increase/decrease and reset. Footer/status shows character count, draft name, save status and copy/clear actions. A Drafts menu exposes saved documents without conflating separate tabs. Collapsible reference chart shows mappings and separator examples.

Single mode has one editable area. Dual mode uses two labeled side-by-side panels: editable source and read-only converted result with direction and swap controls. At narrow widths stack them, retaining source first. Every action has an accessible label and feedback; controls are usable without hover. Avoid replacing native text selection, context menus or expected keyboard shortcuts.

## Settings
Implemented so far ([#123](https://github.com/vchernoy/typebridge/issues/123)): a Settings button opens a non-modal side panel, so a changed rule can be tried in the editor while it stays open. It holds the transliteration shortcut and rules, Autosave and Tab indents. Escape or × closes it and returns focus; Focus mode hides it. Find & Replace and Go to line open on demand (toolbar buttons, Cmd/Ctrl+F, Cmd/Ctrl+G) and close with Escape or ×. The large header is replaced by a top bar: a small TypeBridge name (the page's h1, visually hidden on phones), the document title edited in place, and a ▾ **document menu** with the document list and New, Import, Export TXT/JSON and Delete. Escape, a click outside or an action closes the menu; picking a document with the pointer closes it, while arrow keys keep it open. The editing toolbar holds Undo and Redo (icons with names), To Cyrillic and To Latin (convert the selection), Find, Copy and a ⋯ menu with Go to line… and Clear text…; Focus and Settings sit at the right of the top bar, after the **Latin ⬤ Кириллица** typing-mode switch (a real checkbox with `role="switch"`, named "Кириллица"; clicking a word chooses that side, Space toggles, and the shortcut hint is its description). On phones (≤ 640 px) the top bar wraps into the title row and a row with the switch and icon-only Focus and Settings buttons (names kept for assistive tech), the shortcut hint and toolbar separators are hidden, and margins shrink so the editor starts high on the screen. A compact dot and save label (Saved, Saving…, Not saved or Save failed) follows the document menu. It reflects persistence state even while action feedback is retained below; autosave off shows Not saved. The full status line under the editor remains the announced source for detailed conflict, storage and privacy warnings. The compact label is not a live region and hides with the top bar in Focus mode. Saved texts are called **documents** in the interface ("Documents" list, New document, Untitled document); see [#108](https://github.com/vchernoy/typebridge/issues/108). Code, storage and the export format keep their `draft` names. The full target layout is in #123.

Target Sections: Input and mappings (preset, per-rule edit, conflicts, preview and reset); Editor (height, font size and panel mode); Appearance (system/light/dark); Privacy (auto-save drafts on by default, disable toggle, local-only explanation, retain/delete saved drafts); Drafts (list, open, rename, delete existing drafts; a new independent tab starts blank); shortcuts and restore defaults. Explicitly state local storage is browser/device-specific and may be cleared. Show unsaved-storage errors without removing text.

## Focus documents

Focus mode keeps one line of the top bar above the editor (#104): the same document title (rename in place), the ▾ document menu (switch, New, Import, Export, Delete), the save state, the Latin ⬤ Кириллица switch and Exit focus. There is no second picker; the controls are the Normal-mode ones. Switching uses the same save, conflict and unsaved-discard handling and stays in Focus mode. The brand, Focus, Settings and the shortcut hint are hidden in Focus mode. On phones the line wraps to two rows (title, menu and save state; then the switch and Exit).

## Responsive and accessibility

Escape closes one visible UI layer before the Focus shortcut: a confirmation dialog first, then Settings, then a document/More menu, then Find/Go to line. This applies even when focus has moved back into the editor. CSS-hidden Focus-mode panels do not intercept it. Composition, repeated/already-handled Escape and collapsed native select popups retain their existing ownership. See [#132](https://github.com/vchernoy/typebridge/issues/132).
Target 320px upward, avoid horizontal scrolling and clipped editor/toolbars; keep controls usable when the mobile keyboard opens. Touch targets at least 44 CSS px where practical. Use real buttons, labels, fieldsets, focus order, keyboard-operable resizing, `aria-live` for concise status, and non-color indicators. Respect reduced-motion, browser zoom and high contrast. Test 200% zoom and screen readers; no automatic focus on load.
