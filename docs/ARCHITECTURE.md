# Architecture

## Platform
Static TypeScript application, built with Vite, rendered in semantic vanilla HTML and CSS, hosted on GitHub Pages at the custom domain `https://typebridge.vchernoy.xyz/` (site root `/`; `vchernoy.github.io/typebridge/` redirects there, [#112](https://github.com/vchernoy/typebridge/issues/112)). No backend. Set Vite `base` appropriately for deployment and test direct asset loading. Development scripts use `npm ci`, typecheck, Vitest, Playwright and `vite build`; pin dependencies via a committed lockfile when scaffolding.

## Current layout and intended boundaries

Current code lives in `src/core/` (transliteration rules; `custom-rules.ts` also loads and saves custom mappings in localStorage, an exception to the pure-core boundary below), `src/editor/` (DOM editing, IndexedDB, recovery and preference helpers), and `src/main.ts` (UI/event integration). The `src/ui/` directory contains layout, panels, menus, confirmation dialogs, transliteration settings and Escape-layer coordination. The `src/state/` and `src/storage/` sections below describe intended responsibilities; those two directories do not exist yet. No refactor is implied by this document.

## Boundaries

- `src/core/`: pure rule compilation, conflict validation and transliteration. Language pack contains id, version, direction, ordered mappings and case/boundary policies; Russian is the first pack. Longest-prefix lookup must resolve overlaps deterministically; reject duplicate input sequences with conflicting outputs and validate empty/unbounded rules.
- `src/editor/`: DOM adapter translating browser `beforeinput`, input, selection and composition events into edits. Do not transform during composition. Browser undo differs across implementations; investigate native editing semantics with Playwright before choosing a method, and document fallback. Maintain caret and selection in UTF-16 offsets; test surrogate pairs and combining characters.
- `src/state/`: typed application state and explicit transitions for modes, document and settings. Derive output from source, never mutate it independently. Mode switch preserves text and protects destructive changes.
- `src/storage/`: versioned settings in localStorage and documents in IndexedDB, with document auto-save enabled by default and user-disableable; handle storage errors. Store a stable document ID for tab reload (sessionStorage is a hint, not an exclusive lock); a fresh tab opens the most recently saved document, and a Documents picker opens existing documents. Browser duplicate-tab behavior may clone sessionStorage: transactional per-document revision checks prevent silent overwrites; stale edits are saved as visible conflict-copy documents. Debounce writes, flush on visibility/page lifecycle where possible, handle quota errors and provide export/copy fallback. Never overwrite recoverable data on parsing failure. Storage may be unavailable or cleared by browsers; do not promise durability.
- `src/ui/`: accessible controls, layout, theme tokens, resize and clipboard integration; use textContent/value rather than HTML insertion for user input. No third-party scripts or telemetry.

Input processing for live editing needs bounded context around the caret to recognize digraphs, avoid rewriting unrelated text, and reset at boundaries and mode changes. Paste behavior, ambiguous sequences, capitalization, deletion and undo are first-class test cases. Batch conversion is a separate pure operation; reverse transliteration is potentially ambiguous and lossy.

## Split workspace and editing ownership

[#175](https://github.com/vchernoy/typebridge/issues/175) is the current plan for **several editor windows in one browser tab** (iframe instances with the same Web Lock / fence / saved-version signals as separate tabs). See [ADR 175](adr/175-editor-windows.md). [#159](https://github.com/vchernoy/typebridge/issues/159) W1–W4 (routing `?doc=&mode=view`, comparison companion, metadata-only `BroadcastChannel`, per-document ownership) are **kept**. The in-page split (workspace companion / live mirror / dual `BoundSession`, S2–S5b) was **removed in #175 step 10**; do not reintroduce it. Cross-window Edit here (#164) stays paused; same-tab focus handoff is defined in ADR 175. Ownership remains one lock/fence per document for cooperating windows/tabs; conflict-copy CAS remains the safeguard for non-cooperating versions. Prefer new modules over growing `main.ts` (#99). This is not #7 derived Latin/Cyrillic dual-panel, #39 URL sharing or cross-device sync.

Same-origin iframes in one tab share `sessionStorage`. Step 2 scopes tab-local keys (`activeDraft`, pending backups, Replace text, writing-position namespaces, update-notice dismissal) by an opaque `?window=` id (`src/view/window-id.ts`). Step 9 keeps the **Find query** on the unscoped `typebridge.find.query.v1` key so every window shares the last search. Absent or invalid `window` keeps today’s unscoped key names so the top-level editor and existing tests stay stable. `journalTab` remains a per-load UUID (not sessionStorage). Find CASE/REGEX stay in `localStorage` (shared by design).

Step 3 adds a **host page** (`host.html` / `src/host/`) that embeds editor iframes with stable window ids and `?embed=1`. The host registers the service worker and shows the update notice. Step 5 adds the **free-layout window manager** on the host (New/Close, drag, resize, snap, tile, keyboard move/resize, layout in localStorage, cap 4). Step 6 adds Settings → Layout (Auto / Free / Stacked), capability-based phone stacking with a height grip, and host Focus mode that maximizes the active window. Step 7 moves the **Settings panel to the host**; preference changes apply live to every window via localStorage plus same-tab `typebridge-prefs` events (and direct iframe hooks). Latin/Кириллица mode chrome stays in each window and stays shared. Standalone `/` remains the current entry (existing e2e unchanged); cutover of `/` to the host is a later step.

Step 4 adds **same-document focus handoff** (`src/view/handoff.ts`, `src/view/focus-handoff.ts`): pointer/focus in a read-only window’s text asks the same-tab owner to flush and yield (in-memory snapshot when Autosave is off); cross-tab uses metadata-only `BroadcastChannel` and shows **Edit here** when the owner still has private text; a suspended owner may be taken with `steal: true` after a short timeout. Keystrokes during the handoff are buffered.

## Quality and deployment
Unit tests cover rules, conflicting mappings, case, Unicode, boundaries, storage validation and transactional concurrency. Browser tests cover typing, selection, IME where automation permits, clipboard fallback, resize, mobile layout, persistence and keyboard navigation. Manual testing remains necessary for real IMEs, screen readers and mobile devices. CI runs quality checks and a Chromium/Firefox/WebKit matrix on pull requests. Pages deploys from main; for how main revisions are checked before deployment ([#75](https://github.com/vchernoy/typebridge/issues/75)), consult the workflow YAML and [deployment notes](PREVIEW.md). Successful Actions runs and real-device/production verification are separate evidence.

## IndexedDB persistence and durability

Documents and their undo/redo histories are stored in IndexedDB. Existing localStorage document data is ignored and is never deleted or rewritten. The editor waits for initialization before accepting edits. Saves are serialized per tab and compare document revisions within the write transaction; stale edits become separate visible conflict copies. The same transaction also verifies this window's edit-ownership fence (#159 W4); a fence mismatch aborts the write instead of creating a copy. Deletion also checks the revision. Failed writes leave the current text in memory with an error and block document switches until saved or explicitly discarded. Export or copy unsaved text before closing. Browser termination can interrupt an asynchronous write, and browser storage may be cleared or evicted; beforeunload, pagehide and background flushing are best effort and do not guarantee an IndexedDB commit. A tab-scoped sessionStorage snapshot can recover unsaved edits after reload or same-tab navigation; it is revision-checked before being committed and may be unavailable, exceed quota, or be lost when the tab closes.

### Status line

The status line shows both save state and feedback from user actions. A background save replaces only save-progress messages such as "Saving…" or a failure it resolved; it never replaces newer action feedback (for example "Select text to convert") or a conflict-copy notice, and a failed background save keeps newer action feedback that already shows the same warning. A warning about data at risk is derived from state rather than from the displayed text, and every later action message (Copy, Export, Convert and others) is shown together with it: browser storage unavailable (failed or blocked initialization, or a database upgrade in another tab), a failed save while autosave is on, or unsaved edits while autosave is off (worded so both text and title are clearly not saved and will be lost on reload, including silent background-tab discard on iPhone/Safari). Copying or exporting does not save the document, so it does not clear the warning. Typing does not clear it either: while storage is unavailable the warning stays in place of "Saving…", and after a failed save the progress message says the text stays unsaved until a save succeeds. The warning clears only when the risk is resolved: a successful save, turning autosave back on and saving, or loading another document after the edits are discarded. Storage problems last until the page is reloaded; a conflict-copy notice or a failed delete is shown together with the storage warning. When autosave is toggled, a preference-write error is shown in front of the save state at that moment. Conflict-copy feedback is tracked separately from save progress/failure, so a failed follow-up save, a failed sessionStorage reload backup, and a later storage upgrade cannot erase it. It belongs to the current document and clears on a document switch or a newer explicit action (such as Copy/Export, Delete failure feedback, or toggling autosave when the toggle itself did not create the notice). The conflict notice is rendered in its own polite live region so each save-progress update does not re-announce it; a later identical conflict copy still re-announces by clearing the region before rewriting it. Status body and separator text are written only when they change. A conflict first created by the switch's pre-load flush is not written to the live region while the switch is in progress; switchDraft announces it once on success (left-document wording with the opened document's save state) or on abort/failure (standard conflict wording). persist() and switchDraft() return whether that flush created a conflict copy. A second identical conflict copy re-announces by clearing the live region and rewriting it on a following microtask. If that switch then fails to open the target, the conflict notice stays with the open-failure message, and a later background save does not replace that action while the notice remains. Import may call switchDraft and then announce success without clearing a conflict that flush just created. Turning autosave off while a save is in flight keeps a conflict notice created by that save before offering to delete the saved copy. Document-list refresh failures from save and switch share one attachment gate that ignores newer action feedback; save-state updates clear a stale list-refresh suffix; the suffix comes before the latest risk warning without duplicating a warning already shown as the primary, and strips only a trailing period (not an ellipsis). A successful save or retry confirms with "Saved locally" while retaining pending conflict feedback.

### Emergency text recovery

When autosave is enabled, each editing event synchronously writes a temporary localStorage snapshot keyed by a page instance and document ID. It includes text, title, revision and timestamp, but no undo/redo history. IndexedDB remains authoritative; a snapshot is removed only when its exact version has been committed. Other snapshots are shown as explicit recovery choices and are always saved as separate IndexedDB documents. A stable snapshot ID makes retry after an interrupted recovery idempotent. Recovery does not automatically replace the editor or an existing document. Turning autosave off stops writing new snapshots; prior unsaved snapshots remain recoverable. Storage errors display a warning, and browser storage eviction, quota, crashes, and private browsing can still prevent recovery. Recovery copies do not reconstruct unsaved undo/redo history.

Recovery discovery verifies exact title and text against IndexedDB before clearing a matching journal entry. A per-page Web Lock suppresses recovery prompts while its owner page remains alive, including duplicate tabs. Snapshot changes are coalesced and unchanged panels are not rebuilt. If ownership cannot be verified, users must explicitly inspect potential backups and are warned that another tab might still be open. A confirmed discard removes only the exact displayed entry; never infer permission to discard from a timestamp. Locks are released by the browser when the owning page terminates. Recovery remains subject to browser storage and lifecycle limitations.
