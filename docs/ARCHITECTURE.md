# Architecture

## Platform
Static TypeScript application, built with Vite, rendered in semantic vanilla HTML and CSS, hosted under GitHub Pages project path `/typebridge/`. No backend. Set Vite `base` appropriately for deployment and test direct asset loading. Development scripts use `npm ci`, typecheck, Vitest, Playwright and `vite build`; pin dependencies via a committed lockfile when scaffolding.

## Boundaries

- `src/core/`: pure rule compilation, conflict validation and transliteration. Language pack contains id, version, direction, ordered mappings and case/boundary policies; Russian is the first pack. Longest-prefix lookup must resolve overlaps deterministically; reject duplicate input sequences with conflicting outputs and validate empty/unbounded rules.
- `src/editor/`: DOM adapter translating browser `beforeinput`, input, selection and composition events into edits. Do not transform during composition. Browser undo differs across implementations; investigate native editing semantics with Playwright before choosing a method, and document fallback. Maintain caret and selection in UTF-16 offsets; test surrogate pairs and combining characters.
- `src/state/`: typed application state and explicit transitions for modes, draft and settings. Derive output from source, never mutate it independently. Mode switch preserves text and protects destructive changes.
- `src/storage/`: versioned settings in localStorage and drafts in IndexedDB, with draft auto-save enabled by default and user-disableable; handle storage errors. Store a stable draft ID for tab reload (sessionStorage is a hint, not an exclusive lock); a fresh tab opens the most recently saved draft, and a Drafts picker opens existing drafts. Browser duplicate-tab behavior may clone sessionStorage: transactional per-draft revision checks prevent silent overwrites; stale edits are saved as visible conflict-copy documents. Debounce writes, flush on visibility/page lifecycle where possible, handle quota errors and provide export/copy fallback. Never overwrite recoverable data on parsing failure. Storage may be unavailable or cleared by browsers; do not promise durability.
- `src/ui/`: accessible controls, layout, theme tokens, resize and clipboard integration; use textContent/value rather than HTML insertion for user input. No third-party scripts or telemetry.

Input processing for live editing needs bounded context around the caret to recognize digraphs, avoid rewriting unrelated text, and reset at boundaries and mode changes. Paste behavior, ambiguous sequences, capitalization, deletion and undo are first-class test cases. Batch conversion is a separate pure operation; reverse transliteration is potentially ambiguous and lossy.

## Quality and deployment
Unit tests cover rules, conflicting mappings, case, Unicode, boundaries, storage validation and transactional concurrency. Browser tests cover typing, selection, IME where automation permits, clipboard fallback, resize, mobile layout, persistence and keyboard navigation. Manual testing remains necessary for real IMEs, screen readers and mobile devices. CI workflow is staged until the scaffold exists; Pages workflow is manual and must not publish before the application is ready. Enable Pages source “GitHub Actions” in repo settings when deployment is authorized.

## IndexedDB persistence and durability

Drafts and their undo/redo histories are stored in IndexedDB. Existing localStorage draft data is ignored and is never deleted or rewritten. The editor waits for initialization before accepting edits. Saves are serialized per tab and compare document revisions within the write transaction; stale edits become separate visible conflict copies. Deletion also checks the revision. Failed writes leave the current text in memory with an error and block document switches until saved or explicitly discarded. Export or copy unsaved text before closing. Browser termination can interrupt an asynchronous write, and browser storage may be cleared or evicted; beforeunload, pagehide and background flushing are best effort and do not guarantee an IndexedDB commit. A tab-scoped sessionStorage snapshot can recover unsaved edits after reload or same-tab navigation; it is revision-checked before being committed and may be unavailable, exceed quota, or be lost when the tab closes.

### Status line

The status line shows both save state and feedback from user actions. A background save replaces only save-progress messages such as "Saving…" or a failure it resolved; it never replaces newer action feedback (for example "Select text to convert") or a conflict-copy notice, and a failed background save keeps newer action feedback that already shows the same warning. A warning about data at risk is derived from state rather than from the displayed text, and every later action message (Copy, Export, Convert and others) is shown together with it: browser storage unavailable (failed or blocked initialization, or a database upgrade in another tab), a failed save while autosave is on, or unsaved edits while autosave is off. Copying or exporting does not save the draft, so it does not clear the warning. Typing does not clear it either: while storage is unavailable the warning stays in place of "Saving…", and after a failed save the progress message says the text stays unsaved until a save succeeds. The warning clears only when the risk is resolved: a successful save, turning autosave back on and saving, or loading another draft after the edits are discarded. Storage problems last until the page is reloaded. When autosave is toggled, a preference-write error is shown in front of the save state at that moment.

### Emergency text recovery

When autosave is enabled, each editing event synchronously writes a temporary localStorage snapshot keyed by a page instance and document ID. It includes text, title, revision and timestamp, but no undo/redo history. IndexedDB remains authoritative; a snapshot is removed only when its exact version has been committed. Other snapshots are shown as explicit recovery choices and are always saved as separate IndexedDB drafts. A stable snapshot ID makes retry after an interrupted recovery idempotent. Recovery does not automatically replace the editor or an existing draft. Turning autosave off stops writing new snapshots; prior unsaved snapshots remain recoverable. Storage errors display a warning, and browser storage eviction, quota, crashes, and private browsing can still prevent recovery. Recovery copies do not reconstruct unsaved undo/redo history.

Recovery discovery verifies exact title and text against IndexedDB before clearing a matching journal entry. A per-page Web Lock suppresses recovery prompts while its owner page remains alive, including duplicate tabs. Snapshot changes are coalesced and unchanged panels are not rebuilt. If ownership cannot be verified, users must explicitly inspect potential backups and are warned that another tab might still be open. A confirmed discard removes only the exact displayed entry; never infer permission to discard from a timestamp. Locks are released by the browser when the owning page terminates. Recovery remains subject to browser storage and lifecycle limitations.
