# Architecture

## Platform
Static TypeScript application, built with Vite, rendered in semantic vanilla HTML and CSS, hosted on GitHub Pages at the custom domain `https://typebridge.vchernoy.xyz/` (site root `/`; `vchernoy.github.io/typebridge/` redirects there, [#112](https://github.com/vchernoy/typebridge/issues/112)). No backend. Set Vite `base` appropriately for deployment and test direct asset loading. Development scripts use `npm ci`, typecheck, Vitest, Playwright and `vite build`; pin dependencies via a committed lockfile when scaffolding.

## Current layout and intended boundaries

Current code lives in `src/core/` (transliteration rules; `custom-rules.ts` also loads and saves custom mappings in localStorage, an exception to the pure-core boundary below), `src/editor/` (DOM editing, IndexedDB, recovery and preference helpers), `src/view/` (an editing window's document state and behavior), `src/ui/` (controls, panels and menus), `src/host/` (the multi-window host page) and `src/styles/`. The `src/state/` and `src/storage/` sections below describe intended responsibilities; those two directories do not exist yet. No refactor is implied by this document.

### Code map

[#99](https://github.com/vchernoy/typebridge/issues/99) split the editor page's `src/main.ts` (about 3,000 lines) into focused modules with no behavior change. Each module's header comment says what it owns; this is the index.

- **`src/main.ts`** (editor page entry, about 1,000 lines) reads the page's elements and wires the modules together. New behavior belongs in a module, not here.
- **Shared state.** `view/editor-state.ts` is the window's core document state (open database, shown document, save failure, edit block, ownership, transition flags). Modules take it plus a typed `deps` object of the few functions they call, created as `createX(state, statusLine, deps)`.
- **Saving and storage:** `view/saver.ts` (debounced Autosave under the ownership fence; write gate `mayWrite` = !`privateNow`), `view/autosave-toggle.ts` (per-document Autosave / go-private last save), `editor/privacy.ts` (`privateNow`, Private session, document Autosave checked state; #257), `view/reload-backup.ts` (sessionStorage bridge for reloads), `view/recovery.ts` (emergency journal, #53), `editor/change-log.ts` (pure four-field change records and replay, #37 R2c), `view/change-writer.ts` (one record per edit while writes are allowed, in change-id order; saves record `upTo`), `view/boot.ts` (startup and which document to show, pure `chooseBootDocument`).
- **Documents:** `view/documents.ts` (switch, new, delete), `view/document-sync.ts` (cross-window saved/renamed/deleted signals), `view/deleted-input.ts` (a document deleted elsewhere), `view/viewer-mode.ts` (read-only comparison window), `view/leave-guards.ts` (update reload and closing a host window).
- **Editing ownership and handoff (#159 W4, #175):** `view/edit-access.ts` (acquire, install, lose, freeze), `view/takeover.ts` (take over after a yield, retry, Edit here), `view/held-edits.ts` (quiet-reader title edits and control clicks held until editing arrives), with protocol rules in `view/ownership.ts`, `view/handoff.ts` and `view/focus-handoff.ts`.
- **Share links (#39):** `editor/share-link.ts`, the pure, versioned `#doc=` link format with size limits; `read.html` with `read/main.ts`, the reading page `/#doc=` forwards to; the host's `?open=<id>` shows a saved copy in a window; `ui/share-dialog.ts`, Documents → Share link… ([sharing](SHARING.md)).
- **Host↔window contract:** `view/embed-api.ts` (the typed list of calls and test knobs), `view/embed-hooks.ts` (this window's side), `view/prefs-sync.ts` and `view/prefs-apply.ts` (shared preference changes).
- **Editor-page UI:** `ui/status-line.ts` (single writer of the status line and conflict live region; rules in `editor/status.ts`), `ui/title-edits.ts`, `ui/tab-indent.ts`, `ui/preference-warning.ts`, `ui/export-import.ts`, `ui/find-goto-bars.ts`, `ui/comparison-open.ts`, plus the earlier `ui/` panels and menus.
- **Host page:** `host/main.ts` (entry), `host/window-manager.ts` (windows, drag/resize, layout modes, Focus), `host/window-title.ts` (the title-bar field), `host/layout.ts` (pure geometry), `host/settings.ts`.
- **Styles:** `src/style.css` imports `src/styles/*.css` in cascade order; later files override earlier ones, so keep the order. Both pages load all of them.

## Boundaries

- `src/core/`: pure rule compilation, conflict validation and transliteration. Language pack contains id, version, direction, ordered mappings and case/boundary policies; Russian is the first pack. Longest-prefix lookup must resolve overlaps deterministically; reject duplicate input sequences with conflicting outputs and validate empty/unbounded rules.
- `src/editor/`: DOM adapter translating browser `beforeinput`, input, selection and composition events into edits. Do not transform during composition. Browser undo differs across implementations; investigate native editing semantics with Playwright before choosing a method, and document fallback. Maintain caret and selection in UTF-16 offsets; test surrogate pairs and combining characters.
- `src/state/`: typed application state and explicit transitions for modes, document and settings. Derive output from source, never mutate it independently. Mode switch preserves text and protects destructive changes.
- `src/storage/`: versioned settings in localStorage and documents in IndexedDB, with per-document Autosave on by default and a shared Private session that disables saving everywhere (#257); handle storage errors. Store a stable document ID for tab reload (sessionStorage is a hint, not an exclusive lock); a fresh tab opens the most recently saved document, and a Documents picker opens existing documents. Browser duplicate-tab behavior may clone sessionStorage: transactional per-document revision checks prevent silent overwrites; stale edits are saved as visible conflict-copy documents. Debounce writes, flush on visibility/page lifecycle where possible, handle quota errors and provide export/copy fallback. Never overwrite recoverable data on parsing failure. Storage may be unavailable or cleared by browsers; do not promise durability.
- `src/ui/`: accessible controls, layout, theme tokens, resize and clipboard integration; use textContent/value rather than HTML insertion for user input. No third-party scripts or telemetry.

Input processing for live editing needs bounded context around the caret to recognize digraphs, avoid rewriting unrelated text, and reset at boundaries and mode changes. Paste behavior, ambiguous sequences, capitalization, deletion and undo are first-class test cases. Batch conversion is a separate pure operation; reverse transliteration is potentially ambiguous and lossy.

## Split workspace and editing ownership

[#175](https://github.com/vchernoy/typebridge/issues/175) is the current plan for **several editor windows in one browser tab** (iframe instances with the same Web Lock / fence / saved-version signals as separate tabs). See [ADR 175](adr/175-editor-windows.md). [#159](https://github.com/vchernoy/typebridge/issues/159) W1–W4 (routing `?doc=&mode=view`, comparison companion, metadata-only `BroadcastChannel`, per-document ownership) are **kept**. The in-page split (workspace companion / live mirror / dual `BoundSession`, S2–S5b) was **removed in #175 step 10**; do not reintroduce it. Cross-window Edit here (#164) stays paused; same-tab focus handoff is defined in ADR 175. Ownership remains one lock/fence per document for cooperating windows/tabs; conflict-copy CAS remains the safeguard for non-cooperating versions. Add new behavior as modules rather than growing `main.ts` (see Code map, #99). This is not #7 derived Latin/Cyrillic dual-panel, #39 URL sharing or cross-device sync.

Same-origin iframes in one tab share `sessionStorage`. Window ids scope active-document hints, pending backups, writing positions and update-notice dismissal. Find/Replace text is now document content (#257 step 2b), not a shared Find key or per-window Replace key. Legacy search-content keys are removed without migration. Match case/Regex remain app-wide localStorage settings. `journalTab` remains a per-load UUID. Search queries may still appear in a gated document reload backup; never in independent content keys.

Step 3 adds a **host page** (`host.html` / `src/host/`) that embeds editor iframes with stable window ids and `?embed=1`. The host registers the service worker and shows the update notice. Step 5 adds the **free-layout window manager** on the host (New/Close, drag, resize, snap, tile, keyboard move/resize, layout in localStorage, cap 4). Step 6 adds Settings → Layout (Auto / Free / Stacked), capability-based phone stacking with a height grip, and host Focus mode that maximizes the active window. Step 7 moves the **Settings panel to the host**; preference changes apply live to every window via localStorage plus same-tab `typebridge-prefs` events (and direct iframe hooks). Latin/Кириллица mode chrome stays in each window and stays shared. Step 11 packages verification evidence under [evidence/175](evidence/175/README.md) and ships must-have host a11y: each window shell is a named `role="region"` (`aria-label` = document title; `data-window-id` retained), and **F6** cycles focus to the next window’s editor (raises z-order in free layout; works in stacked; respects host Focus maximize). **Cutover:** `/` (`index.html`, entry `src/host/entry.ts`) is the host. The single editor is `/editor.html` (`src/main.ts`): host windows load it with `?window=…&embed=1`, and the W2 comparison popup opens `/editor.html?doc=…&mode=view`. An inline script in `index.html` forwards pre-cutover editor links on `/` (`doc`, `mode`, `window` or `embed` params) to `/editor.html`, and the host does not start while forwarding. `/host.html` redirects to `/`. The host and its editor windows are same-origin documents that call each other through functions on `window`; [`src/view/embed-api.ts`](../src/view/embed-api.ts) is the one typed list of those calls (what each window exposes, what the host exposes) and of the test-only timing knobs e2e sets, which ship in the deployed build because CI tests the same build Pages publishes. The service worker falls back to `editor.html` for offline `/editor.html` navigations and to `index.html` (the host) otherwise. Most standalone-editor e2e tests target `/editor.html`; host tests target `/`.

Step 4 adds **same-document focus handoff** (`src/view/handoff.ts`, `src/view/focus-handoff.ts`): pointer/focus in a read-only window’s text asks the same-tab owner to flush and yield (in-memory snapshot when the owner is private / cannot write); cross-tab uses metadata-only `BroadcastChannel` and shows **Edit here** when the owner still has private text; a suspended owner may be taken with `steal: true` after a short timeout. Keystrokes during the handoff are buffered.

## IndexedDB persistence and durability

Documents and their undo/redo histories are stored in IndexedDB. Existing localStorage document data is ignored and is never deleted or rewritten. The editor waits for initialization before accepting edits. Saves are serialized per tab and compare document revisions within the write transaction; stale edits become separate visible conflict copies. The same transaction also verifies this window's edit-ownership fence (#159 W4); a fence mismatch aborts the write instead of creating a copy. Deletion also checks the revision. Failed writes leave the current text in memory with an error and block document switches until saved or explicitly discarded. Export or copy unsaved text before closing. Browser termination can interrupt an asynchronous write, and browser storage may be cleared or evicted; beforeunload, pagehide and background flushing are best effort and do not guarantee an IndexedDB commit. A tab-scoped sessionStorage snapshot can recover unsaved edits after reload or same-tab navigation; it is revision-checked before being committed and may be unavailable, exceed quota, or be lost when the tab closes. Reload-backup cleanup uses content/history equality or an unchanged backup captured before the save began, never wall-clock ordering. Each backup write carries a fresh private identity token (stripped when reading document data), so a newer write during an in-flight save cannot be mistaken for the earlier backup even if timestamps and content repeat. Cleanup runs only after the transaction commits.

**Private mode (#257 step 1).** Writes (full save, change log, journal, reload backup, leave flush) are gated by `mayWrite()` = !`privateNow()`. `privateNow` is true when the shared Private session is on (`typebridge.autosave.v1` off) **or** the open document’s optional `private` flag is set. The editor chrome **Autosave** checkbox is per document (unchecked = private); Settings holds only **Private session**, which forces every window’s checkbox off. Going private freezes a pre-private snapshot (and its content revision), switches immediately, then `persistLastBeforePrivate` commits that freeze with `private: true` (or a flag-only update on failure), then offers **Keep saved copy / Delete saved copy**. Deleting removes the IndexedDB row, its change records, and its journal/reload backups; the document stays private in memory only. Turning the global Private session on makes one last save of a dirty, non-document-private shown document **without** setting `private: true`. That last-save prefers the last snapshot taken while writes were still allowed (updated on editable input), so a delayed cross-tab `storage` delivery cannot commit text typed after `mayWrite()` already went false (#260). Same-tab prefs sync uses a CustomEvent; **other top-level tabs** listen for the `storage` event on `typebridge.autosave.v1` so each tab runs that session last-save / checkbox mirror path (#260). **Fail closed (preference read):** when `localStorage` throws, `privateSessionOn()` returns the last successfully observed session value; if nothing has been read yet (and nothing has been written via `setPrivateSessionOn`), it treats the session as on so `mayWrite()` is false. It does not invent a “saving allowed” default that would open IndexedDB writes after a blocked preference read. Clearing all local data (global) is a later #257 step.

### Status line

The status line shows both save state and feedback from user actions. A background save replaces only save-progress messages such as "Saving…" or a failure it resolved; it never replaces newer action feedback (for example "Select text to convert") or a conflict-copy notice, and a failed background save keeps newer action feedback that already shows the same warning. A warning about data at risk is derived from state rather than from the displayed text, and every later action message (Copy, Export, Convert and others) is shown together with it: browser storage unavailable (failed or blocked initialization, or a database upgrade in another tab), a failed save while autosave is on, or unsaved edits while autosave is off (worded so both text and title are clearly not saved and will be lost on reload, including silent background-tab discard on iPhone/Safari). Copying or exporting does not save the document, so it does not clear the warning. Typing does not clear it either: while storage is unavailable the warning stays in place of "Saving…", and after a failed save the progress message says the text stays unsaved until a save succeeds. The warning clears only when the risk is resolved: a successful save, turning autosave back on and saving, or loading another document after the edits are discarded. Storage problems last until the page is reloaded; a conflict-copy notice or a failed delete is shown together with the storage warning. When autosave is toggled, a preference-write error is shown in front of the save state at that moment. Conflict-copy feedback is tracked separately from save progress/failure, so a failed follow-up save, a failed sessionStorage reload backup, and a later storage upgrade cannot erase it. It belongs to the current document and clears on a document switch or a newer explicit action (such as Copy/Export, Delete failure feedback, or toggling autosave when the toggle itself did not create the notice). The conflict notice is rendered in its own polite live region so each save-progress update does not re-announce it; a later identical conflict copy still re-announces by clearing the region before rewriting it. Status body and separator text are written only when they change. A conflict first created by the switch's pre-load flush is not written to the live region while the switch is in progress; switchDraft announces it once on success (left-document wording with the opened document's save state) or on abort/failure (standard conflict wording). persist() and switchDraft() return whether that flush created a conflict copy. A second identical conflict copy re-announces by clearing the live region and rewriting it on a following microtask. If that switch then fails to open the target, the conflict notice stays with the open-failure message, and a later background save does not replace that action while the notice remains. Import may call switchDraft and then announce success without clearing a conflict that flush just created. Going private while a save is in flight keeps a conflict notice created by that save; the Keep/Delete prompt follows the last pre-private save (#257). Document-list refresh failures from save and switch share one attachment gate that ignores newer action feedback; save-state updates clear a stale list-refresh suffix; the suffix comes before the latest risk warning without duplicating a warning already shown as the primary, and strips only a trailing period (not an ellipsis). A successful save or retry confirms with "Saved locally" while retaining pending conflict feedback.

### Emergency text recovery

When Autosave is on, a temporary localStorage snapshot (text, title, find, replace, revision and timestamp; no undo/redo history) is written only while the IndexedDB change log cannot protect the latest edit (#37 R2c 2d-2): before the first committed save of a run, after a change-record write has failed, while records are held behind a save that has not committed, or when IndexedDB is unusable (missing database or a storage problem). The change-log writer exposes `protects()` for that gate and notifies when protection is lost asynchronously (failed append or failed held save), so the journal is written immediately with the current text and title without waiting for the next keystroke. **Accepted loss window (maintainer):** the journal is deliberately *not* written on every keystroke while a live run covers the edit. `protects()` means a live non-failed run with no hold — not that every append for the latest keystroke has already reported complete. The newest change record can still be queued or in flight (normally well under a few milliseconds); that is the R2c window “change records whose transaction has not reported complete.” Last committed snapshot + durable change records are enough to recover; rewriting the whole document to localStorage on each keystroke is not the design. The sync journal also does not reliably cover whole-browser kills (see evidence below). While `protects()` is true and IndexedDB is usable, editing writes no new journal entry. This tab's own superseded working journal (for example written while a first save held records, then left behind because exact-version cleanup matches the committed text) is cleared once the change-log queue is idle and the writer still protects — so a stale “emergency backup unavailable” warning from an earlier journal-write failure does not linger after the change log is protecting again. Other tabs' entries are left alone until exact-version cleanup or an explicit discard. IndexedDB remains authoritative; a snapshot is removed only when its exact version has been committed, exactly recovered as a copy, or cleared as this tab's superseded working journal after protection returns. Other snapshots are shown as explicit recovery choices and are always saved as separate IndexedDB documents. A stable snapshot ID makes retry after an interrupted recovery idempotent. Recovery does not automatically replace the editor or an existing document. Turning Autosave off stops writing new snapshots; prior unsaved snapshots remain recoverable. Storage errors display a warning, and browser storage eviction, quota, crashes, and private browsing can still prevent recovery. Recovery copies do not reconstruct unsaved undo/redo history. A successful synchronous localStorage write does not prove durability against whole-browser termination. Renderer-crash and transaction-abort tests, plus the observed process-kill gap, are distinguished in [recovery interruption evidence](evidence/37/README.md).

Recovery discovery verifies all four fields against IndexedDB before clearing a matching journal entry. A per-page Web Lock suppresses recovery prompts while its owner page remains alive, including duplicate tabs. Snapshot changes are coalesced and unchanged panels are not rebuilt. If ownership cannot be verified, users must explicitly inspect potential backups and are warned that another tab might still be open. A confirmed discard removes only the exact displayed entry; never infer permission to discard from a timestamp. Locks are released by the browser when the owning page terminates. Recovery remains subject to browser storage and lifecycle limitations.

### Change log (#37 R2c)

Database version 6 (#257 step 2a) retains the `changes` store keyed `[documentId, seq]` and clears its incompatible older records during upgrade, without migrating them. Document rows retain text/title and may add `find`/`replace`; absent search fields mean empty. There is one gap-free sequence, run, queue, failure rule and snapshot `upTo` for all four fields. Each record names its `field` (`text`, `title`, `find`, `replace`) and stores `{documentId, seq, run, field, value, previous}` when both the old and new values are under 256 UTF-16 code units, or `{documentId, seq, run, field, change: [position, deleted, inserted], length}` otherwise. Value records require the current field to equal `previous`; deltas also cover long→short edits. All four fields stop together at a missing/invalid record, foreign run or non-fitting change (`replayDocument`). They cannot recover at different cuts.

The existing ownership fence, full-save cadence and save anchor rules remain. A run starts at a full save, never uncommitted shown content. If any field in the saved snapshot is not produced by the log, later records wait for that save and are dropped if it fails. The save stores all four values with one `upTo` and removes covered records by one range delete in the same transaction; it first preserves any distinct prefix from other runs as a recovered copy, then removes those other runs. Search-only differences count in salvage and cleanup. A conflict copy atomically removes only its editing run's records from the original document id, because the edits are now durable in the copy. Other runs and documents are preserved. Conflict/recovered copies carry all four fields; replay does not reconstruct unsaved history. Reload backups and fallback journals carry the four values and compare them all before clearing; the same `mayWrite()` gate applies. Records captured before privacy can finish queued writes; private edits never create records.

**Document-bound UI (#257 step 2b).** `view/document-search.ts` binds Find/Replace to the shown document. Their edits and independent histories use the normal dirty/save, shared change-log, fallback journal and reload-backup paths. The title's existing Editor history is also captured/restored alongside body/Find/Replace. Switching documents restores all four histories inside the loading transition; interrupted IME snapshots are invalidated on external load/restore. Privacy changes never reload, swap or clear the displayed fields/history: only the existing write gates change.

Viewers and ordinary non-owning readers can search, with per-document values/histories held in window memory. Saved-version refreshes preserve that local search. Persistence-facing capture in a reader uses canonical row search, excluding local queries even from a late fallback callback. Automatic ownership acquisition drops local search and restores canonical values without scheduling a save. Explicit ownership takeover can adopt a reader's search; private same-tab handoff carries all four fields/histories through existing direct in-memory calls. Cross-tab channels remain metadata only. Search inputs freeze during transfer; IME in any field blocks a handoff.

The host's layout serializer stores geometry/document ids only, with no title strings. Its live title field may display a private title in memory, while `typebridge.host.windows.v1` cannot contain it; reloading reads the stored title. No title swapping is introduced. Step **2c** keeps a missing viewer’s requested identity for signal/focus recreation, refreshes the writable snapshot after startup recovery bumps the content revision, and routes storage preference sync through the normal session deduplication/reversal guard; new-private-document identity traces and clear-data UX remain steps 3–4. The localStorage journal above remains as a fallback only when the change log cannot protect the latest edit (#37 R2c 2d-2); it is no longer written on every keystroke while a live run covers the edit. The accepted in-flight gap above applies here too: a record counts as protecting once the run is live, not only after its IndexedDB transaction reports complete. When the user explicitly discards unsaved edits (closing a window after a failed save, switching documents after confirming discard, or the same consent on Edit-here handoff), both the journal entry and every change-log record for that document under the live ownership fence are removed so a later owner does not salvage what was discarded. Destructive discard cleanup on window close is deferred until the host commits the leave; canceling the leave thaws a frozen editor and keeps journal/change-log recovery. A second close for the same window is ignored while prepare/commit is in flight. **Discard changes and reload** does not clear change records. Under the private-mode rule (#257), those records hold only text from before the document went private, which is the state recovery is meant to show; #255 tracks the checks that nothing typed while private is ever written or recovered.


### New private documents (#257 step 3)

A private document at revision 0 has no persistent identity. Its active-document hint, position, journal and reload backup are removed or suppressed, and the host stores no document ID for that window. Live title chrome remains in memory; private unsaved titles are excluded from other windows’ title enumeration. Reload therefore starts a fresh document instead of restoring this identity. Its own Documents list can show it as Private / Not saved; other windows only list committed rows.

Acquiring an absent document in a private session does not acquire shared editing ownership. A new public document may reserve the Web Lock in memory, but defers the IndexedDB fence claim until its first write; releasing an unwritten reservation stores nothing. A private revision-zero window releases that reservation. First real save claims ownership before committing, and normal hints/layout/position recording resumes. A privacy change during first-save acquisition cancels that save. A never-saved document has no final pre-private snapshot to commit; existing saved documents keep the last-save behavior. Explicit Import still creates a saved document, including during a private session.

Step 4 (Clear local data) is separate. This does not clear other saved documents or settings.


If the first documents transaction has already started when Autosave is unchecked, going private waits for its result before deciding whether the document is still revision zero. Metadata stays suppressed during that wait, but the in-flight write retains its fence. A successful commit follows the saved-document private-flag and Keep/Delete path using the frozen pre-switch fields/revision; abort leaves an editable, trace-free revision-zero document without a replacement save. Delete sends the normal deleted signal and clears pre-switch backups; Keep relies on the committed row without stale-backup recovery. The existing toggle gate refuses a concurrent Autosave transition.


Private session also waits for a revision-zero first save to settle before its final identity synchronization. Cancellation or abort releases the unsaved document’s shared reservation/fence; a successful commit keeps normal saved-document ownership and metadata without setting the per-document private flag. The session still blocks all later content writes, and turning it off resumes normal Autosave. No replacement final save is made for a document that remained unsaved.


### Clear local data (#257 step 4)

Documents offers a separately confirmed **Clear this document’s saved data…** action. It waits for a pending save, removes the saved row and shared log under the ownership fence, clears crash/reload backups and view metadata, and sends metadata-only deletion/clearing notifications. Live text and all Editor histories remain in memory as a fresh private scratch identity. Cancel is nondestructive. Existing Autosave → Keep/Delete behavior is unchanged.

Settings offers **Clear local data…**, separate from Reset settings. It deletes the content-only IndexedDB database; versionchange closes existing connections and invalidates pending access before deletion completes. Already-started transactions drain before the database is erased. Open editors retain their fields/history privately and reject subsequent content writes until reload; viewers retain a read-only copy. Pending deletion says “Storage is being cleared”; successful deletion and metadata cleanup say “Storage was cleared”. Browser storage failures report incomplete erasure rather than success.

Only known TypeBridge content keys are removed from local/session storage: journals, reload backups (including retired namespaces), active hints, positions, legacy drafts/search text and host layout. Settings, Private session, other applications’ storage and offline app assets are kept. A metadata-only channel plus transient storage event notifies other tabs; each tab removes its own session data. Host caches suppress cleared identities until their editor acknowledges them and stop persisting layout after clear-all. No entered text is transmitted or logged.
